本文件是给 AI 编码代理（ZCode / Claude Code / Cursor）的执行规范。
**读完本文件后，你应该能在不询问任何问题的前提下，产出第 13、14、…… 册，且与已有 12 册版式、深度、风格完全一致。**

## 2. 手册结构（章节顺序固定，不得增删一级标题）

| 章 | 内容 | 硬性要求 |
|---|---|---|
| 封面 | 编号、专题名、副标题、"七维学习法"标识、版本日期 | 副标题必须是一句**论点**，不是"概述" |
| 使用说明 | 6 周排期表 + 每周产出物 + 关闭标准 | 排期表必须列"本周产出物"列 |
| 1 | 本专题定位 | 1.1 为什么单列 / 1.2 事故画像 / 1.3 能力目标（五层：知道→会算→会查→会建→会影响）/ 1.4 边界声明 |
| 2 | **A 规范标准** | 四层表：国内强制 / 国内支撑 / 国际 / 项目所在国与业主。每层给"用途"而非只列编号。末尾**必须**有"标准编号年代号需核对现行有效版本"的提示 |
| 3 | **B 技术原理** | **6 张计算卡**。每张格式见 3.1 |
| 4 | **C 危险辨识** | 4.1 失效模式清单（**≥25 条**，按危害/能量传播路径分类，不按设备分类）/ 4.2 三张领结图 / 4.3 本专题特有的误判清单 |
| 5 | **D 控制措施** | 层级控制逐级展开，每级给"实际削减量"而非"有/没有"。必须有一节讲**最被低估的那一级** |
| 6 | **E 检查验证** | 6.1 台账（3–5 本，标注哪本最常缺失）/ 6.2 制度与流程 / 6.3 现场动作（要能"用手做"，不是"看"）/ 6.4 复验触发条件 |
| 7 | **F 案例复盘** | 8–10 类必读案例 + 案例卡模板（八要素）。**最值钱的字段是"被忽略的预警信号"** |
| 8 | **G 输出转训** | 8.1 45 min 课件大纲（分钟级）/ 8.2 班组预判问题 ≥8 条（要写真实问法，含"抬杠式"提问）/ 8.3 环境定制（按项目所在国写两段） |
| 9 | 达标自测 | 20 题，≥18 分方可关闭。含 ≥4 道计算题 |
| 10 | 关闭标准 | 5–8 条，**必须包含"产出物被项目实际采用并查出真实隐患"** |

### 2.1 计算卡的格式（最关键，6 张全部照此）

```
3.N  【卡 N】标题（≤14 字，点明算什么）

3.N.1 要回答的问题      —— 一句话，现场会怎么问
3.N.2 公式与参数        —— 公式 + 每个符号的含义与单位
3.N.3 算例              —— 表格：3–5 组参数 → 结果 → 现场含义
3.N.4 结论              —— 一句话，必须是"能改变做法"的判断
3.N.5 常见错误          —— 2–3 条现场真实做法，说明为什么错
```

**六张卡的选择规则（按此优先级排序）：**
1. 伤害发生的物理量（能量、力、浓度、时间）
2. 判据与限值（合格/不合格的分界线在哪）
3. 常被忽略的放大因子（超载、叠加、衰减）
4. 时间窗口（救援、暴露、逃逸）
5. 资源需求（水量、人力、风量）
6. 管理量（若有：成本、抽样、指标）

**算例必须是真实量级**，能对上现场设备铭牌或规范数值。禁止用 1、10、100 这类整齐但不真实的数。

## 3. 写作硬规则

1. **中文，术语首次出现给英文原文**（如"悬吊不耐受 Suspension Intolerance"）。
2. **数字优先于形容词。** 写"33.7 Ω"，不写"电阻较大"。
3. **每节开头先给判断，再给论证。** 不要"首先……其次……"。
4. **禁止伪根因**：意识淡薄、违章作业、培训不到位、责任心不强——不得作为结论。
5. **禁止模糊量词**：若干、适当、必要时、加强、严格。换成数值或条件。
6. **每个"要求"必须配一个"怎么验"**。做不到验证的要求不写。
7. **语气**：对一个有经验、但没算过这个数的同行说话。不解释常识，不吹捧读者。
8. **标准编号一律不带年代号**，或带年代号时紧接"（核实现行版）"。
9. **不得编造事故案例。** 案例写成"类型描述 + 公开可查的调查报告名称"，不虚构具体项目、单位、人名。
10. **单页表与手册结论必须一致**，不得出现手册说 A、检查表查 B。

## 4. 单页检查表规范

| 项 | 要求 |
|---|---|
| 页面 | A4 纵向，页边距 上下 0.9 / 左右 1.2 cm。**目标双面**：正面=信息栏+检查项；背面=STOP 红线+记录区+签字 |
| 正文字号 | 6.8–7.2 pt（不得低于 6.5）；表头 7.5 pt（黑体） |
| 结构 | 标题条（中英）→ 信息栏（项目/日期/班次/编号）→ **A 区通用** 8–12 项 → **B 区专项** 5–8 项 → **STOP WORK 红线** 6–8 条 → 签字栏 4 方 → 脚注 |
| 条目写法 | 中文一行 + 英文一行；必须是**可判定**的（能打 √/×），不是"注意""加强" |
| STOP 区 | 每条以"任何人有权停止作业"的语义开头，用红底或粗体 |
| 脚注 | 必须写"本表为班前检查，不替代定期检验/检测/体检" |
| 中英对照 | 英文用短句祈使句，不用完整从句（省版面） |

**容量经验（LibreOffice 实测）：** 6.8–7.2 pt 时单面约容纳「14–16 个两行条目」。检查项 ≤16 条的表可达标准双面（T01–T03）；17 条以上的表自然溢出至 3 页（T04–T12 现状），收敛手段按优先级：英文行精简 20–30% → 同类条目合并（每表 ≤2 条、需本人同意）→ 禁止再降字号。

**生成后必须跑** `finalize_checklist.py`：在 STOP 标题前插显式分页（红线区永不从页中间开始），并压缩所有表格单元格左右内边距（108→45 dxa）以减少英文折行。

## 5. 生成流程（必须按序执行，每步验证后再进下一步）

```bash
# 1. 写四个内容脚本（先写完再跑，不要边写边跑）
# 2. 汇总脚本
build_topic{NN}.py

# 3. 生成
python build_topic{NN}.py

# 4. 质检（必须先过 qc_scan.py，再做别的）
python 90_工具与规范/qc_scan.py "0N_.../T{NN}_.../手册.docx"

# 5. 生成检查表并后处理（finalize 插分页 + 压缩单元格边距）
python build_checklist{NN}.py
python 90_工具与规范/finalize_checklist.py "0N_.../T{NN}_.../检查表_A4双面.docx"
python 90_工具与规范/qc_scan.py "0N_.../T{NN}_.../检查表_A4双面.docx"
# 页数验证：LibreOffice 转 PDF → pymupdf 数页，目标 2 页、上限 3 页

# 6. 更新 catalog.json
# 7. 更新 README.md 索引表（三张表之一）
```

**第 4 步不通过（输出任何"可疑"词）必须修完再往下走。** 忽略它会让整册出现中英混杂的乱码片段，是不可交付的。

## 6. docxkit.py API（唯一允许的排版入口）

```python
import docxkit as K
from docx import Document
from docx.shared import Cm, Pt

doc = Document()
K.setup(doc, margin_lr=2.4, margin_tb=2.0)   # 若存在；否则手动设 section

K.H(doc, '标题文字', level=1)      # 1/2/3 级标题，黑体
K.P(doc, '正文段落')               # 宋体 10.5，首行缩进
K.B(doc, '要点文字', num=1)        # 编号要点（num 给数字）
K.NOTE(doc, '提示文字')            # 灰色小字提示
K.TBL(doc, ['表头1','表头2'], [[...],[...]], widths=[4,12])   # 表格
K.KV(doc, [('键','值'),...])       # 两列信息表
K.PAGE(doc)                        # 分页，若存在；否则 doc.add_page_break()
```

**表格铁律：`widths` 总和 ≤ 16.4 cm**（A4 可用宽度 16.6，留余量）。超了会溢出页面。

## 8. 禁止事项

1. 不得新建排版函数（一律用 docxkit）。
2. 不得输出纯提纲——每一节都要有实质内容。
3. 不得把"要求"写成"应当注意"。
4. 不得复制已有 12 册的段落（交叉处只写一行引用）。
5. 不得跳过 qc_scan.py。
6. 不得在未确认标准现行版本时，把年代号写成确定事实。
7. **不得把伪根因（意识淡薄/违章作业/培训不到位）写进任何结论。**
